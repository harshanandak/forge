## 2. Push for questions and approvals

**iPhone and iPad.** Web Push starts at iOS and iPadOS 16.4 for Home Screen web apps. Open the installed app, sign in, tap **Enable notifications**, and allow the prompt. Apple requires a direct user gesture and a visible notification for each push. The owner controls Focus and notification settings. Apple uses its own push service with no Apple Developer Program membership for standards-based Web Push. Apple’s newer Declarative Web Push can skip the worker on supported versions. Keep the worker path for iOS 16.4 and Chrome. [WebKit iOS 16.4](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [Apple sending guide](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers), [WebKit declarative push](https://webkit.org/blog/16535/meet-declarative-web-push/).

**Android Chrome.** Open the site or its installed copy, tap the same enable button and allow the site prompt. Installation is optional for Chrome’s site push. If notifications are blocked, check the site setting and Android notification settings. Feature-detect the APIs and use `PushManager.subscribe` with `userVisibleOnly: true` and the Forge VAPID public key. The service worker receives the push and displays a notice even with the page closed, subject to delivery and device settings. [Chrome Android prompts](https://developer.chrome.com/blog/notification-prompts-android), [Chrome site notification settings](https://support.google.com/chrome/answer/3220216?co=GENIE.Platform%3DAndroid), [MDN subscription](https://developer.mozilla.org/en-US/docs/Web/API/PushManager/subscribe), [W3C Push API](https://www.w3.org/TR/push-api/).

**Sending and cost.** Generate one stable P-256 VAPID key pair for Forge. Publish the public key and keep the private key in a Worker secret. VAPID signs the sender’s token. The subscription’s endpoint, public encryption key and auth secret enable encrypted payload delivery and belong in private, bounded per-owner storage. The Worker can send an HTTPS POST directly to each browser-issued endpoint using `fetch`, with Web Crypto support for the signing and encryption primitives. The browser selects the push service. Chrome uses Firebase Cloud Messaging behind its browser-issued endpoint. Forge can send directly with VAPID on both platforms for zero broker fees and no Firebase project setup. Keep subscriptions owner-authenticated. Validate HTTPS push-provider destinations and disable redirects when sending, so the subscription endpoint cannot become an arbitrary outbound request. Keep the cryptographic implementation small and proven against both providers. [Chrome Web Push protocol](https://web.dev/articles/push-notifications-web-push-protocol), [Chrome VAPID support](https://developer.chrome.com/blog/web-push-interop-wins), [RFC 8292 VAPID](https://www.rfc-editor.org/rfc/rfc8292), [RFC 8291 encryption](https://www.rfc-editor.org/rfc/rfc8291), [Workers Fetch](https://developers.cloudflare.com/workers/runtime-apis/fetch/), [Workers Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/), [Worker secrets](https://developers.cloudflare.com/workers/configuration/secrets/).

The incremental target is **$0** using the existing origin and the Workers Free plan, within its limits. Cloudflare lists 100,000 Worker requests per day, 10 ms of Worker CPU per invocation, and 50 subrequests per invocation. The existing SQLite Durable Object storage type has separate Free limits, including 5 million rows read and 100,000 rows written per day and 5 GB total storage. Reuse it when storing private subscriptions within a capped project allocation. A second database, paid plan and paid broker are unnecessary for the proposed owner-only volume, subject to measuring sender CPU and checking the account’s headroom at implementation. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/).

Keep notices generic on the lock screen, for example “Forge needs your input.” A tap may open the normal app landing page. The owner answers in the chat. Use a short push TTL bounded by the request’s remaining lifetime. Apple limits one payload to 4 KB and can discard stored messages. Remove expired subscriptions on permanent endpoint failure, and let an owner resubscribe if permission or the VAPID key changes. A successful push response means the push service accepted the message. Forge still needs a reply or acknowledgement from the owner before recording that the person acted. [Apple delivery behavior](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers), [RFC 8030](https://datatracker.ietf.org/doc/html/rfc8030).

## 3. Passkey approval later

**Expected on both platforms.** Use WebAuthn in a foreground page on the same HTTPS origin that owns the passkey. Apple supports web passkeys in Safari on iOS 16 and Google documents Chrome passkeys on Android 9 or later. An installed website still uses the web API under its own origin, so ordinary WebAuthn should work in both installed apps. That installed-mode conclusion is an inference from the platform docs. Check enrollment and confirmation on both target phones before relying on it. Use feature detection and keep chat usable when no authenticator is available. [Apple web passkeys](https://developer.apple.com/videos/play/wwdc2022/10092/), [WebKit Safari 16](https://webkit.org/blog/13152/webkit-features-in-safari-16-0/), [Google Android and Chrome passkeys](https://developers.google.com/identity/passkeys/supported-environments), [W3C WebAuthn](https://www.w3.org/TR/webauthn-3/).

A passkey gives cryptographic proof that the registered credential answered a fresh server challenge. Require user verification and check the signed verification flag to require the authenticator’s local identity check, which can be a screen-lock PIN or biometric. Forge would first enroll the credential under verified owner sign-in. After the owner reviews the exact action and taps **Confirm**, store a one-time random challenge bound server-side to the owner, project, pending request, choice, operation digest, revision and expiry. Check the assertion signature, credential, challenge, origin, relying-party ID and presence and verification flags. Recheck the pending request and consume the challenge with the decision in one transaction. That gives Forge evidence of fresh, verified credential use for one bound operation. The authenticator prompt verifies the user. Forge’s page supplies the operation details, so the assertion cannot independently establish what the person read or understood. Synced passkeys can also be used on another authorized device. [W3C assertion verification](https://www.w3.org/TR/webauthn-3/#sctn-verifying-assertion), [W3C challenges](https://www.w3.org/TR/webauthn-3/#sctn-cryptographic-challenges), [Google passkey sync](https://developers.google.com/identity/passkeys/supported-environments).

Keep forge-1673’s text reply as the normal approval when the owner is in chat. Its evidence comes from the trusted chat sender and a reply matched to the exact pending request. A passkey adds a fresh user-verification step, credential enrollment and recovery, and a browser step. Where a later owner policy requires that extra evidence, the owner can open Forge from its icon and confirm a pending action in the signed-in app. A push can prompt attention without carrying an approval URL or token. Forge’s existing link-based lane approval code is evidence of the current design. The Owner’s newer decision is the constraint for this phone proposal. [Current lane URL generation](https://github.com/harshanandak/forge/blob/8c0273e00e41781135b1bf4ec393179c5dfbe0f6/cloud/src/lane-approval.ts#L186-L211).

## 4. Urgent escalation

**Owner-gated. Default is no automatic calls.** The web option is a visible notice, potentially with Web Push `Urgency: high` and a short TTL. This asks the push service to try sooner. Focus, Do Not Disturb, notification permission and device connectivity still control what the owner sees. A web notification cannot request Apple’s native Critical or Time Sensitive interruption levels through the standard Notifications API. Critical Alerts require an approved Apple entitlement and can bypass mute and Focus. Android’s native notification channels and full-screen call notifications use native OS features with their own rules. An ordinary Forge alert should stay within web notification controls. [Apple Web Push urgency](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers), [Web Notifications standard](https://notifications.spec.whatwg.org/), [Apple interruption levels](https://developer.apple.com/design/human-interface-guidelines/managing-notifications), [Android call notifications](https://developer.android.com/develop/connectivity/telecom/voip-app/notifications).

A `tel:` link opens the viewer’s dialer to a known number. The person confirms or taps Call. Forge incurs no extra service fee and the caller’s existing carrier rates apply. That lets the owner call someone after reading the alert. For Forge to ring the owner’s phone on its own, a server needs a carrier-connected voice API, SIP/PSTN gateway or an existing authorized calling system, plus a permitted caller identity. As one priced example, Twilio lists **US$0.0699 per minute** to call India and international numbers **from US$1.15 per month**. India caller ID restrictions apply. Its trial restricts calls and is a test path. Before enabling any automatic call, the owner would need to choose what counts as urgent, who may be called, quiet hours, retry cap and spend cap. [Apple phone links](https://developer.apple.com/library/archive/featuredarticles/iPhoneURLScheme_Reference/PhoneLinks/PhoneLinks.html), [Android dialer intent](https://developer.android.com/guide/components/intents-common#Phone), [Twilio Call API](https://www.twilio.com/docs/voice/api/call-resource), [Twilio India pricing](https://www.twilio.com/en-us/voice/pricing/in), [caller ID limits](https://help.twilio.com/articles/57566259695003), [Twilio trial](https://www.twilio.com/docs/usage/trials/try-out-voice).

## 6. Native wrapper

Capacitor becomes worth considering when a measured requirement needs an OS capability the website lacks, such as a native notification category, share target integration or managed store distribution. It wraps existing web assets in native iOS and Android projects and exposes native plugins. Its push plugin adds platform setup for APNs and Android Firebase. A wrapper also brings signing, native toolchains, release upkeep and app distribution. Apple Developer Program distribution normally costs **US$99 per year** and Google Play registration is **US$25 once**. A wrapper cannot grant Apple’s Critical Alerts entitlement or supply a carrier connection. **Skip it now.** Installation, reports, ordinary alerts and passkeys all have a web path. [Capacitor runtime](https://capacitorjs.com/docs), [Capacitor push plugin](https://capacitorjs.com/docs/apis/push-notifications), [Apple membership](https://developer.apple.com/programs/enroll/), [Google Play registration](https://support.google.com/googleplay/android-developer/answer/6112435/).
