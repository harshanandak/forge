# Runtime API

`BlockCatalog(capture, trust, runtimeOptions)` in `catalog.ts` is the injected host for real CLI/MCP dispatch. `block add <path>` captures and validates a candidate, registers its operations without admitting them, and reuses admission for an identical digest. `block check <path>` performs capture/schema/declaration/composition validation without registering anything; failures carry findings in the result envelope. Both return the block ID, digest and admission state. `block admit <digest>` requires a human caller and device context, recaptures the candidate and refuses changed bytes before recording admission. Add/admit refuse dry runs without mutation. Admission never grants operation effects.

Captured docs must validate as `DocsRecords` and cover every declared operation. CLI/catalog/MCP receive the authored records, including descriptions and examples. Long block names use a bounded instance key with a digest suffix; the full block ID remains in results.

`createNodeBlockCatalog(baseDirectory, trust)` under `src/adapters/node-runtime/catalog.ts` supplies file capture and async-capable isolation. It accepts directories and installed package names (including scoped names), searching ancestor `node_modules` directories without executing or installing packages. Candidate state is host-local and in memory. Trust is ephemeral by default or uses the embedding's injected `TrustRecords`; durable candidate/config/admission storage and wiring the standalone executable across invocations remain LI/L5 integration. The standalone stub still injects `emptyCatalog`; this API does not silently choose storage or authenticate human callers. Help and MCP hide unadmitted operations, while the host's `list()` reports `admitted: false` and named agent calls return `ADMISSION_REQUIRED`.

`captureBlock(root, capture)` reads a bounded, root-contained set of regular files, validates the manifest and schemas, and retains immutable text plus an exact byte digest. `Catalog(config, captures)` resolves nouns, renames and typed slots without activating code. `list()` and `describe()` are reads. `addBlock(root, trust, capture)` captures and reports whether the same bytes already have admission; it does not write config or storage.

`Runtime(catalog, trust, options).invokeText(bytes)` is the outside JSON boundary. `invoke(value)` is for trusted embeddings with parsed JSON values. Both use the same resolve, context bind, trust check and awaited invocation path. The returned value is always a result envelope. A refused admission opens no services. A refused output is never returned as a success.

The current author ABI is `forge.author/v2`, profile `trusted-action/v2`. Self-contained CommonJS exports operation-name functions through `module.exports`. Each receives `{input, config, services, signal, deadline}` and returns a JSON value or a Promise of one. `signal` is the runtime-owned AbortSignal; `deadline` is an absolute Unix time in milliseconds. Existing `forge.author/v1` / `trusted-action-sync/v1` manifests are accepted and run through this same evaluator. Synchronous handlers need no source changes.

An operation may declare `timeoutMs`. Its effective budget is the lesser of that declaration and the runtime's `limits.timeoutMs` (1000 ms by default); without a declaration the runtime budget applies. The budget includes service and evaluator acquisition. `invoke` and `invokeText` accept a second `{signal}` argument for caller cancellation. Deadline and cancellation return `INVOCATION_TIMEOUT` and `INVOCATION_CANCELLED`; effects may already have happened, so reconcile before repeating. VM evaluation, output inspection, thenable assimilation and async continuations run under the remaining deadline. The evaluator pumps a private microtask queue until completion, so a service Promise can settle without letting a later CPU loop escape the VM deadline.

Runtime service wrappers recheck current admission and effect grants before each service use, then revoke all nested clients and cached or bound methods on success, rejection, timeout and cancellation. Post-settlement calls throw `ForgeFailure` with `SERVICE_EXPIRED`, before calling the provider. This applies to owned and borrowed clients, including namespaced and leased state. Owned handles still close; borrowed handles remain owned by their embedding. Providers expose service clients as object properties, not by returning new unscoped clients from methods. Returned JSON data is not a service.

ProcessPort clients (the structural `resolve`/`run` interface) automatically receive the invocation signal and remaining budget. Settlement cancels unfinished calls, and the runtime drains them before releasing state or returning. The process adapter uses a host-selected supervisor, waits for tree termination on abort, and reports `INCOMPLETE / PROCESS_CLEANUP_FAILED` if termination cannot be confirmed. Future network/native clients must observe the factory's scope signal and deadline, and prevent deferred writes after cancellation. There is currently no network port. Cancellation cannot undo an already committed effect.

**Open containment blocker:** a child command can detach a descendant and exit successfully before cancellation. Process groups and taskkill do not provide ownership after that escape. Detached descendants are not yet contained; the async contract is not merge-ready until the owner resolves the required boundary or an OS containment provider closes it.

This is trusted code, never a security sandbox or a preemption guarantee for blocking native host clients. There is no package loader, ambient executable access or outside lifecycle hook. The embedding remains responsible for native I/O limits, effects and lease fencing at the write boundary.

The embedding's service factory receives the selected instance, bound context, and frozen operation/effects scope with signal and deadline for this invocation. Construct clients exposing only methods authorized by scope.effects; another operation's grants never supply write methods. The embedding is trusted to enforce this boundary. Capture takes a catalog-local FileCapturePort typed with L1's borrowed handle; src/adapters/fs-capture supplies Node file reads and path containment. Use `catalog.bindings(instance)` to build only the declared clients. A nonempty binding set without a factory returns `PROVIDER_MISSING` with status `INCOMPLETE` before activation. The factory owns partial-open rollback (the contract's `openAll` helper provides it). Return the contract's owned or borrowed handle; owned handles close on success, refusal and deadline, and borrowed handles are left to their owner. Cleanup failure is INCOMPLETE.

`TrustStore` is a human-controlled authority object; never inject it into block services. The transport authenticates the caller identity instead of taking a human claim from untrusted input. Admission and effect grants bind to exact captured bytes. Persistence is injected through `TrustRecords` and must use the state owner; the default map is ephemeral and creates no files. `secretReference` accepts only a validated named reference and never resolves plaintext.

`assembleCoreManifest(base, fragments)` merges the area-owned typed declarations (`operations.ts`) and refuses duplicates. Check, test and build generate `src/generated/core-manifest.json` from these declarations through `tools/gen/core.ts`; the assembled manifest is never committed. Catalog call schemas reference the canonical invocation and result schemas, registered from the generated contract documents. Relative schema references are followed through the captured file set regardless of filename suffix; those files participate in the byte digest, so changes require fresh admission. Assembly supplies executable core handlers. Package assembly must expose the catalog/runtime/trust APIs and copy their JSON assets; those shared build/export changes are owned separately. The installed artifact proof uses the built runtime API directly until the generated transports are connected.

## Declared deadlines

There is no implicit operation timeout. Declare `timeoutMs` in each operation, or supply a runtime budget for a legacy manifest. All timeout values are integer milliseconds from **1 through 2147483647**. The floor avoids a zero/unbounded VM timeout; the ceiling is the largest delay that Node timers represent without overflow. These bounds are safety constraints, not a recommended duration.

| Key                                                               | Meaning                                                                                        | Bounds                                     |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Manifest `operations.<operation>.timeoutMs`                       | The operation author's budget.                                                                 | Integer 1..2147483647 ms                   |
| Config `blocks.<instance>.operationTimeouts.<declared-operation>` | Overrides that operation's budget. Keys use the original operation name, before local renames. | Integer 1..2147483647 ms; at most 512 keys |
| Config `runtime.timeoutMs`                                        | Host ceiling for operation budgets; supplies a budget when a legacy operation has none.        | Integer 1..2147483647 ms                   |
| Embedding `RuntimeOptions.limits.timeoutMs`                       | Additional host ceiling; supplies a budget if no declaration/config budget exists.             | Integer 1..2147483647 ms                   |

Resolution: use the instance override, otherwise the operation declaration, otherwise the configured host budget. Apply both configured host ceilings when present. Missing all budgets refuses with `INPUT_INVALID` before opening services. Config values are validated by the canonical schema, so CLI and MCP use the same rules. Adjusting a budget grants no effect or execution authority.

The budget starts before service acquisition. Service and evaluator acquisition consume it; the evaluator receives only the remaining time. `RuntimeOptions.clock` accepts `ClockPort` for deterministic elapsed-time checks. Production uses the wall clock when no clock is injected. The synchronous evaluator cannot preempt a blocked native client; clients still need their own I/O bounds. Expiry after an effect requires reconciliation and does not roll back the write. Async cancellation and process containment remain a separate contract change.

The shipped work block declares 15000 ms for operations with effects and 5000 ms for reads; project detection declares 5000 ms. Packed durable-write fixtures declare 15000 ms. These are author declarations, adjustable with the config above, rather than core policy. The packed first-slice journey prints `DEADLINE_MEASUREMENT` for the existing `semver.mark` durable state write and its MCP round trip separately. The write measurement surrounds the state client call inside the handler; it is not a wall-time regression assertion or a retry.
